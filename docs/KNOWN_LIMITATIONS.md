# Known Limitations

1. **Production auth** — Local Supabase Auth is wired; production IdP/OAuth is not configured. Known-password users exist only in an explicitly invoked, loopback-guarded fixture.

2. **Scaffold modules** — `cost-control`, `performance`, `administration`, `master-data` remain placeholders. **Forecasts** has a functional draft/submit/approve page on P3 branch (partial).

3. **Delegated approvals** — Approvals inbox includes a delegated tab; delegation records are not yet wired.

4. **Procurement documents** — Contracts, invoices, payments, and credit notes tabs are scaffolded; commitments and vendors are populated.

5. **RLS coverage** — All 55 public tables enable and force RLS. The effective 85-policy matrix is generated by `npm run test:db`; a count alone is not assurance.

6. **pgTAP** — SQL test placeholder remains; executable tests use `scripts/run-db-tests.mjs`.

7. **Service role** — Retained server-only for future admin tooling; not used in user workflow paths.

8. **Windows build intermittency** — Next.js production build may fail with worker exit `3221226505` on memory-constrained Windows hosts. Classified as **resource/environment limitation**, not a reproducible application defect. Linux CI is authoritative.

9. **Supabase Docker Desktop gateway refresh** — On Windows, reset can replace the Auth container while Kong retains its old address. `npm run db:wait-local` gates readiness and refreshes only this repository's gateway if that condition persists. Test retries remain disabled.

10. **Remaining production blockers** — P3 addresses import/export security, reporting grain, EVM inputs, active tenant context, and partial localization. Delegated approvals, full procurement lifecycle, production OAuth, complete i18n, and transactional forecast RPCs remain open. See `CODEX_AUDIT_REPORT.md` remediation annotations.
